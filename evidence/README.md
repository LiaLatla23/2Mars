# Project evidence · 2Mars

This folder complements the official NASA Space Apps Project Submission. It does **not** replace or repeat the submission form. Its purpose is to make implementation, scientific grounding, educational intent and testing easier to inspect in the repository.

## Evidence index

| Document | What it helps verify |
|---|---|
| [Challenge alignment](CHALLENGE_ALIGNMENT.md) | Where the challenge's mission-design goals appear in the implemented game. |
| [Educational design](EDUCATIONAL_DESIGN.md) | Intended learning opportunities and the gameplay activities that support them. |
| [Mission walkthrough](MISSION_CASE_STUDY.md) | A reproducible route through the game and the decisions a reviewer should observe. |
| [Test report](TEST_REPORT.md) | Available automated/manual testing evidence and how to reproduce the automated checks. |
| [AI and asset attribution](AI_AND_ASSET_ATTRIBUTION.md) | Team-confirmed tool use, asset origins and items that still require final verification. |

## Recommended reading order

1. Read the [root README](../README.md) for the project overview and access links.
2. Open the [V4 game guide](../Game-versions/V4/README.md) to play or run the project.
3. Use the documents above to inspect the educational design, implementation and test evidence.
4. Follow the [NASA resource inventory](../research/NASA_RESOURCES_USED.md) and [V4 science traceability](../Game-versions/V4/docs/SCIENCE_TRACEABILITY.md) to verify scientific references.

## Evidence policy

Only claim what can be checked in the current V4 source, a reproducible test, a visible game feature or a team-confirmed production record. Internal playtesting is not external user research. Intended learning opportunities are not measured learning outcomes. Game abstractions are not NASA engineering specifications.
